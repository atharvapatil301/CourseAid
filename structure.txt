/COURSEAID PROJECT STRUCTURE
============================

CourseAid is a full-stack web application built with Flask that serves as a better alternative
to RateMyProfessor. It provides comprehensive course and instructor information with AI-powered
recommendations using RAG (Retrieval-Augmented Generation) architecture.

ROOT LEVEL FILES
================

├── run.py
│   Main entry point for the Flask application. Imports the Flask app instance from the
│   app package and runs the development server on host 0.0.0.0:7860 with debug mode disabled.
│
├── requirements.txt
│   Lists all Python dependencies required for the project including:
│   - Flask & flask-cors: Web framework and CORS handling
│   - psycopg2-binary & pgvector: PostgreSQL database connectivity and vector operations
│   - torch, transformers, sentence-transformers: Machine learning and NLP models
│   - huggingface-hub: Access to Hugging Face models
│   - pydantic: Data validation
│   - python-dotenv: Environment variable management
│
├── Dockerfile
│   Docker container configuration for deploying the application. Uses Python 3.11-slim base
│   image, installs dependencies from requirements.txt, exposes port 7860, and runs the
│   application using run.py.
│
├── README.md
│   Comprehensive project documentation including:
│   - Project introduction and technical specifications
│   - Architecture overview (Flask backend, PostgreSQL with pgvector, Gemma embeddings)
│   - Database design (11 tables with conceptual and logical diagrams)
│   - Installation and setup instructions
│   - Feature walkthrough with screenshots
│   - Troubleshooting guide
│   - Future work and planned enhancements
│
├── .env
│   Environment variables file containing sensitive configuration (git-ignored):
│   - Database credentials (DB_HOST, DB_NAME, DB_USER, DB_PASSWORD, DB_PORT)
│   - Secret key for Flask sessions
│   - API tokens (HF_TOKEN for Hugging Face, GEMINI_API_KEY)
│
├── .env.example
│   Template file showing required environment variables without actual sensitive values.
│   Used as a reference for setting up the .env file.
│
├── .flaskenv
│   Flask-specific environment configuration, typically contains FLASK_APP and FLASK_ENV
│   settings for Flask CLI commands.
│
├── .samplenv / sample.env
│   Sample environment file (duplicate), provides example format for environment variables.
│
├── directory.txt
│   Previously created directory structure documentation (likely outdated compared to this file).
│
├── vercel.json
│   Configuration file for Vercel deployment platform, contains deployment settings and
│   routing rules for hosting the application on Vercel.
│

APP DIRECTORY (./app/)
======================

The main application package containing all the application code organized in MVC pattern.

├── app/__init__.py
│   Application factory and initialization module. Key responsibilities:
│   - Creates Flask application instance with template and static folder configuration
│   - Loads environment variables using dotenv
│   - Configures session cookies (SECURE, HTTPONLY, SAMESITE settings)
│   - Sets up CORS with credentials support for Hugging Face spaces
│   - Applies ProxyFix middleware for proper header handling
│   - Registers authentication blueprint
│   - Imports and registers API routes
│   - Contains commented Hugging Face login initialization


CONFIG SUBDIRECTORY (./app/config/)
====================================

├── app/config/__init__.py
│   Package initialization file for the config module.
│
├── app/config/db_connection.py
│   Database connection management module. Provides:
│   - connect(): Establishes PostgreSQL connection using credentials from environment variables
│   - close(): Closes active database connections
│   - Prints database version upon successful connection
│   - Handles connection errors with psycopg2.Error exceptions
│
├── app/config/PopulateDB.py
│   Database population script for initial data seeding. Contains populateDB class with methods:
│   - populateCoursesTable(): Inserts course data (course_number, course_description)
│   - populateDepartmentsTable(): Inserts department names
│   - populateInstructorsTable(): Inserts instructor names (first_name, last_name)
│   - populateUsersTable(): Inserts user data (username, password, school_year)
│   - populateReviewsTable(): Inserts review data from JSON files in batches
│   - populateCourseEmbeddingsTable(): Generates and stores course description embeddings
│     using Gemma model
│   - populateReviewEmbeddingsTable(): Generates and stores review comment embeddings
│   - populateVotesTable(): Inserts vote data from JSON files
│   - populateCourseSectionTable(): Maps courses to instructors
│   - populateCourseToDepartmentTable(): Maps courses to departments
│   - populateInstructorToDepartmentTable(): Maps instructors to departments
│   - populateUserToCourseTable(): Maps users to enrolled courses
│   Uses tqdm for progress bars and SentenceTransformer for embedding generation.


CONTROLLERS SUBDIRECTORY (./app/controllers/)
==============================================

Contains controller modules that handle request/response logic for different features.

├── app/controllers/__init__.py
│   Package initialization file for controllers module.
│
├── app/controllers/assistant_controller.py
│   Handles AI assistant functionality using RAG architecture:
│   - get_assistant(): Renders the assistant.html template
│   - answer_question(conn): Processes user queries through the AI assistant
│     * Extracts user message from request JSON
│     * Determines query intent (compare, curriculum, qna) using IntentClassifier
│     * Accepts optional intent_hint from frontend
│     * Routes query to appropriate AssistantRoles method based on intent
│     * Returns AI-generated responses as JSON
│
├── app/controllers/index_controller.py
│   Manages home page and search functionality:
│   - index(): Renders the main landing page
│   - search_page(): Renders the search interface
│   - search(): Processes search queries for professors/courses
│     * Supports filtering by department
│     * Handles professor name and course number searches
│     * Returns search results for display
│
├── app/controllers/review_controller.py
│   Handles all review-related operations:
│   - get_user_reviews(conn): Fetches all reviews created by the logged-in user
│   - get_reviews_for_instructor(conn, instructor_name): Retrieves reviews for a specific
│     instructor with validation
│     * Validates instructor existence
│     * Fetches instructor details and associated courses/departments
│     * Retrieves consensus summary (cached summary of all reviews)
│     * Updates summary cache if needed (every 20 new reviews)
│     * Fetches vote information for each review
│     * Returns rendered professor_reviews.html template
│   - review_form(instructor_first, instructor_last): Handles GET/POST for review submission
│     * GET: Renders review form with course selection dropdown
│     * POST: Validates and inserts new review with embeddings
│   - view_reviews(): Displays all reviews (testing endpoint)
│   - edit_review(review_id, conn): Updates existing review via PATCH/PUT request
│   - delete_review(review_id, conn): Deletes review via DELETE request
│
├── app/controllers/user_controller.py
│   Manages user authentication and registration:
│   - register(): Handles user registration (GET shows form, POST creates account)
│     * Validates username uniqueness
│     * Hashes passwords using werkzeug.security
│     * Inserts new user into database
│   - login(): Handles user login (GET shows form, POST authenticates)
│     * Validates credentials
│     * Creates user session on successful login
│     * Redirects to index page
│
├── app/controllers/vote_controller.py
│   Manages voting on reviews:
│   - handle_votes(conn, review_id): Processes upvote/downvote actions
│     * Accepts vote_type from request body ('upvote' or 'downvote')
│     * Checks for existing vote by user on the review
│     * Creates new vote or updates/deletes existing vote
│     * Returns updated vote counts as JSON

│     * compare_professors(): Generates comparison responses for two instructors

│   - MiscellaneousInfoContext: Validates miscellaneous information
│   Ensures data integrity and provides type hints throughout the application.

├── app/models/intructors.py (Note: typo in filename, should be instructors.py)

├── app/models/reviews.py

DATABASE SCHEMA (PostgreSQL)
=============================

The application uses 11 tables:

1. users
   - username (PK)
   - password (hashed)
   - school_year

2. instructors
   - instructor_id (PK, auto-increment)
   - first_name
   - last_name
   - UNIQUE(first_name, last_name)

3. courses
   - course_number (PK, e.g., "CS5200")
   - course_description

4. departments
   - department_id (PK, auto-increment)
   - department_name (UNIQUE)

5. review
   - review_id (PK, auto-increment)
   - comment (TEXT)
   - instructor_first
   - instructor_last
   - username (FK to users)
   - rating (DECIMAL)
   - post_time (TIMESTAMP)
   - last_updated (TIMESTAMP)
   - course_number (FK to courses)
   - FK to instructors(first_name, last_name)

6. votes
   - vote_id (PK)
   - review_id (FK to review)
   - username (FK to users)
   - vote_type ('upvote' or 'downvote')
   - UNIQUE(review_id, username)

7. course_section
   - section_id (PK, auto-increment)
   - course_number (FK to courses)
   - instructor_first
   - instructor_last
   - FK to instructors(first_name, last_name)

8. course_to_department
   - id (PK, auto-increment)
   - course_number (FK to courses)
   - department_name (FK to departments)

9. instructor_to_department
   - id (PK, auto-increment)
   - instructor_first
   - instructor_last
   - department_name (FK to departments)

APPLICATION WORKFLOW
====================

1. User Registration/Login:
   - User accesses /auth/register or /auth/login
   - Credentials validated against users table
   - Session created with user_id on successful login

2. Search for Instructor/Course:
   - User enters search query on index page
   - Search controller queries instructors/courses tables with optional department filter
   - Results displayed with links to instructor profiles

3. View Instructor Profile:
   - User clicks on instructor name
   - System fetches instructor details, courses, departments, and all reviews
   - Consensus summary retrieved from cache or generated if stale
   - Vote information fetched for each review
   - Profile page rendered with all information

4. Submit Review:
   - User navigates to review form for specific instructor
   - Selects course from dropdown (courses taught by instructor)
   - Enters rating and comment
   - Review inserted into database
   - Review embedding generated and stored
   - User redirected to instructor profile

5. Vote on Review:
   - User clicks upvote/downvote button on a review
   - AJAX request sent to /reviews/<review_id>/vote
   - System checks for existing vote:
     * No existing vote: Create new vote
     * Same vote: Delete vote (toggle off)
     * Different vote: Update vote type
   - Updated vote counts returned and displayed

6. AI Assistant Interaction:
   - User enters query in assistant interface
   - Intent classifier determines query type:
     * COMPARE: Comparing two professors
     * CURRICULUM: Course recommendations
     * QNA: General questions about courses/reviews
   - Context builder retrieves relevant data:
     * Uses vector similarity search on embeddings
     * Fetches related course descriptions and reviews
   - LLM generates response using context
   - Response displayed in chat interface

7. Consensus Summary Generation:
   - Triggered when instructor profile is viewed
   - System checks if 20+ new reviews since last update
   - If yes:
     * Fetches all reviews for instructor
     * Sends to LLM with summarization prompt
     * Stores summary in summary_cache.json with timestamp
   - If no: Returns cached summary
